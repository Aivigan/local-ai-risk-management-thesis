# Концепция предлагаемой системы

[ПРЕДЛОЖЕНИЕ] Начальный сценарий — подготовка риск-обзора по разрешённому пакету документов кооперационного проекта.

## Поток обработки
Приём документов → проверка формата и прав → извлечение текста и метаданных → индексирование → поиск подтверждающих фрагментов → формирование проекта риск-карточки → проверка человеком → решение ответственного → журналирование результата.

RAG здесь — предлагаемая схема генерации с извлечением контекста из базы документов. Ссылки на документы не гарантируют истинность вывода: соответствие ответа источнику проверяется отдельно. Реализация и модель пока не выбраны.

## Альтернативы
Сравнить ручной обзор, поиск и проверки по правилам, затем поиск с LLM. Если простая проверка дат решает задачу, не заменять её генерацией.

## Роли
- Владелец процесса утверждает сценарий и критерии успеха.
- Куратор данных проверяет происхождение, доступ и актуальность.
- Аналитик проверяет факты и готовит рекомендации.
- Руководитель принимает решение.
- ИТ/ИБ согласуют размещение, доступ, обновления и журналы.

Это предлагаемые роли, а не описание структуры конкретной организации.

## Этапы и контрольные точки
1. Диагностика: есть измеримый процесс и законные данные.
2. Проектирование: согласованы альтернативы, риски и критерии.
3. Прототип: пройдены функциональные тесты на синтетике.
4. Ограниченный пилот: есть разрешения и ответственная проверка.
5. Решение о масштабировании: подтверждены качество, затраты и допустимость рисков.
На каждом этапе возможны доработка или остановка.

## Оценка
Измерять время вместе с проверкой ответа, точность извлечения фактов, подтверждённость утверждений, пропуски рисков, ложные сигналы, задержку и стоимость запроса. Пороги пока не назначены. Включить тесты противоречивых версий, отсутствующих данных и команд, внедрённых в документы.

## Границы
Никаких автономных внешних действий. Изоляцию, сетевые обращения, резервирование и разграничение доступа проверять отдельно. Локальное размещение не равно доказанной безопасности.
